# OSS — סבב 16: קשרים בין מודולים, דחיפה ל-GitHub

## 1. האיחודים — כקשרים, לא כטופס אחד

כל צירוף שתואר ב-`VALUE-MAP.md` ממומש עכשיו. בתחתית כל רשומה מופיעה שורה
*"קשור לרשומה זו"*: קישור לכל מודול אחר שיש בו רשומות תואמות, עם מספר הרשומות.

**במפורש לא טופס מאוחד.** מסך שמכיל ליד + אנשי הקשר שלו + החשבוניות + המנויים
הוא חלון עם עשרות שדות שאיש לא סורק. שורת קישורים אומרת את אותו הדבר בשורה אחת
ומשאירה כל מודול אחראי על הנתונים שלו.

הקשרים מבוססים על **ערך שכבר קיים בשתי הרשומות** — שם לקוח, ספק, עובד, נכס —
ולכן אין שדות חדשים ואין קישור ידני. 21 קשרים ב-`src/lib/crm/relations.js`,
וקשר שהמודול שלו לא בבנייה פשוט לא מוצג.

## 2. דחיפה ל-GitHub

```bash
export GITHUB_TOKEN=ghp_...
npm run export -- --modules=leads,proposals --github=owner/repo --branch=main
```

וגם מתוך הממשק: `הגדרות → ייצוא (ZIP)` → **דחיפה ל-GitHub**.

* קומיט אחד עם כל הקבצים — **ארבע קריאות API**, לא אחת לכל קובץ. ה-Git Data API
  מקבל תוכן קבצים ישירות בעץ; רק נכסים בינאריים דורשים blob משלהם.
* עובד גם על מאגר ריק לחלוטין (יוצר את הענף הראשון).
* בסיום מוצגת פקודת `git clone` — משם ישר ל-Claude Code.
* אותו מתכנן משמש את ה-ZIP ואת הדחיפה, כך שמה שנוחת במאגר זהה לבית למה שהיה יורד.

**הטוקן לא נשמר בשום מקום.** בממשק הוא בזיכרון בלבד ונמחק בסיום הדחיפה; ב-CLI
הוא נקרא מ-`GITHUB_TOKEN` ולא מהארגומנטים, כדי שלא ייכנס להיסטוריית הפקודות.
שלוש בדיקות אוכפות את זה, כולל שהטוקן אכן מנוקה אחרי דחיפה.

## 3. באג שהבדיקות החדשות חשפו

שדה הלקוח בחשבוניות נקרא `company`, בזמן שהחיפוש בחשבוניות חיפש לפי `client_name`
— שדה שלא היה קיים. **חיפוש לפי שם לקוח בחשבוניות פשוט לא החזיר כלום.**

זה נוצר בסבב שבו הוסר מודול הארגונים: אותה מחרוזת החלפה תפסה קודם את חשבוניות
במקום את אנשי הקשר. תוקן, ונוסף טסט שאוכף ש**כל שדה חיפוש בכל סכימה הוא שדה
שקיים** — ושאין עמודה כפולה ברשימה.
