# פריסה — Vercel / Netlify

## איפה כפתור הייצוא

`הגדרות → אדמין` — כפתור **ייצוא (ZIP)** בראש העמוד. **עובד גם באתר הפרוס**,
לא רק בפיתוח.

הייצוא רץ כולו בדפדפן: קוד המקור מוטמע בבילד דרך `import.meta.glob`, והארכיון
נבנה עם JSZip בצד הלקוח (`src/lib/browserExport.js`). אין שרת, אין API route,
אין תלות ב-Vite dev server. המטען מגיע כ-chunk נפרד שנטען רק כשלוחצים "הורד ZIP".

הדיאלוג מציג רק את המודולים שקיימים **בחבילה הזו** — אם ייצאת חבילה חלקית,
ממנה אפשר לייצא הלאה רק את מה שיש בה.

### אותו דבר משורת הפקודה

```bash
npm run export -- --list                              # רשימת המודולים
npm run export                                        # הכל
npm run export -- --modules=dashboard,tasks,settings
npm run export -- --modules=dashboard --sections=users,branding --out=lite.zip
npm run export -- --no-dev-tools                      # חבילה רזה, בלי כפתור ייצוא
```

שתי הדרכים קוראות ל-`tools/export-core.js` — אותו מתכנן, אותו אימות, אותה גזירת
חבילות. הפלט זהה לבית.

---

## מה מייצא הכפתור

מייצר חבילה שנבנית בעצמה.
הייצוא **מסרב להוריד קובץ שלא היה נבנה**: לפני האריזה הוא פותר כל ייבוא בכל
קובץ שנכלל, ואם משהו לא נפתר — מוחזרת שגיאה עם רשימת הקבצים במקום ZIP שבור.

מה נכלל נקבע ב-**זחילת גרף** מנקודות הכניסה (`index.html`, `src/main.jsx`,
העמודים של המודולים שנבחרו). קובץ שאף אחד לא מייבא — לא נשלח. תלות
חוצת-מודולים נגררת אוטומטית, ולכן ייבוא תלוי לא יכול להיווצר.

## פריסה

### Vercel
```
Framework Preset : Vite
Build Command    : npm run build
Output Directory : dist
```
`vercel.json` שבחבילה כבר מגדיר rewrite לכל הנתיבים אל `index.html` — קישורים
עמוקים (`/projects/abc`) עובדים.

### Netlify
```
Build command    : npm run build
Publish directory: dist
```
`netlify.toml` + `public/_redirects` מגדירים את אותו הדבר.

## משתני סביבה

העתק `.env.example` ל-`.env.local` (או הגדר בממשק של Vercel/Netlify):

| משתנה | תפקיד |
|-------|-------|
| `VITE_OWNER_EMAIL` | המייל שנחשב אדמין ראשון. **חייב להיות מוגדר לכל פריסה.** |
| `VITE_OWNER_NAME`  | שם התצוגה של בעל המערכת |
| `VITE_APP_NAME`    | שם המוצר |
| `VITE_APP_LOGO_URL`| כתובת הלוגו (ברירת מחדל: `/icon-192.png` מקומי) |

אין שום כתובת מייל אישית בקוד. אם לא הוגדר משתנה — נעשה שימוש ב-`admin@localhost`.

## מגבלה שחייבים להכיר

שכבת הנתונים בחבילה המיוצאת (`src/api/client.js`) שומרת הכל ב-`localStorage`
של הדפדפן ומחברת אוטומטית משתמש יחיד. **זו אינה מערכת רב-משתמשים ואין בה אימות.**
מתאים להדגמה, לפיילוט מקומי או לשימוש אישי. למוצר ללקוחות יש להחליף את המודול
הזה בשרת אמיתי (Supabase או API עצמאי) — הוא מרוכז בקובץ אחד בדיוק
בשביל זה.

## החבילה ממשיכה לייצא בעצמה

כברירת מחדל הייצוא כולל את `tools/`, את קובצי הבדיקות ואת `vitest` — כלומר
**החבילה המיוצאת היא מקור לגיטימי לייצוא הבא**. אין צורך לחזור לרפו המקורי
החבילה עצמאית לחלוטין. לחבילה רזה בלי כלי פיתוח: `?devTools=0`.


## הוספת מודול חדש

עורכים קובץ אחד — `src/lib/modules.js`. המסלולים, תפריט הצד, דיאלוג הייצוא
וסינון הקבצים נגזרים ממנו. `npm test` מוודא שהמניפסט תקין.
