# מעבר ל-Supabase

`הגדרות → אדמין → חיבור Supabase`.

## שלושה שלבים

1. **הזן פרטי פרויקט** — כתובת (`https://xxxx.supabase.co`) ומפתח `anon`.
   המערכת דוחה מפתח `service_role` באופן מפורש: הוא חושף את כל הנתונים והוא
   לעולם לא אמור להגיע לצד לקוח.
2. **בדיקת חיבור** — פנייה ל-`/rest/v1/` ותשובה מיידית אם הכתובת או המפתח שגויים.
3. **הרץ את הסכימה** — הכפתור מעתיק SQL שנגזר מהמודולים שבבנייה הזו: טבלה לכל
   ישות, עמודות לפי סוגי השדות, `custom_fields` כ-`jsonb`, `RLS` מופעל ומדיניות
   בסיסית לפי `owner_email`.

הסכימה נגזרת מהמניפסט — מודול חדש מופיע ב-SQL אוטומטית, בלי הגדרה שנייה לתחזק.

## מה עדיין חסר

ההגדרות נשמרות ונבדקות, אבל **שכבת הנתונים הפעילה היא עדיין `localStorage`**.
המעבר בפועל דורש להחליף את `src/api/client.js` בלקוח Supabase. הקובץ בנוי
בדיוק לשם כך: הוא מייצא `entities`, `functions`, `auth` ו-`integrations`, וזו
כל המשטח שהאפליקציה מכירה.

הפאנל מציג אזהרה כשמסמנים "הפעל" בדיוק כדי שלא ייווצר רושם שהמעבר כבר קרה.

ברגע שהלקוח מוחלף, שני הדברים שממתינים לצד שרת נפתרים גם הם: אימות אמיתי
(במקום בדיקת סיסמה בדפדפן) ומנוע שמריץ את האוטומציות.
